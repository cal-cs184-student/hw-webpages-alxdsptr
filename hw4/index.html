Overview

In this homework, we built a cloth simulator based on a mass-spring model. We first model the cloth as a grid of masses connected by springs which represent different kinds of constraints. Then we simulate the motion of the cloth under gravity and forces from the springs by using numerical integration. We also implemented collision handling between the cloth and other objects such as spheres and planes, as well as self-collision handling to prevent the cloth from intersecting itself. Finally, we implemented shaders to render the cloth with various visual effects.

I found the use of spatial hashing to accelerate self-collision detection to be a particularly interesting design choice, simple yet efficient. In addition, I found shader programming remarkable: we only need to write the vertex shader and fragment shader, and the GPU automatically handles all the remaining steps such as rasterization and interpolation, performing them in parallel. This achieves both high efficiency and great flexibility.

Part 3: Handling collisions with other objects

For the sphere, I strictly followed the instructions. First, I computed the position's direction from the sphere's origin, and computed the distance between them by taking the norm of this vector. Then I checked whether this distance is smaller than the radius of the sphere; if it is, it indicates that a collision has occurred. Next, I computed the tangent point by adding the unit of this direction vector times the radius to the origin, and computed the correction vector as the tangent point minus the last position. Finally, I assigned the position as the last position plus the correction times (1 - friction).

For the plane, I first computed the signed distances from both the last position and the current position to the plane by taking the dot product of the vector from a point on the plane to each position with the plane's normal. Then I checked whether the product of these two signed distances is negative; if it is, it indicates that the point mass has crossed the plane and a collision has occurred. Next, I computed the vector from the last position to the current position, then obtained the parametric ratio of the tangent point along this vector by dividing the old signed distance by the dot product of this vector and the normal, and thereby derived the tangent point. I then determined the target point by offsetting the tangent point along the normal by a small SURFACE_OFFSET, toward the side where the point mass was before crossing over (i.e., using the normal when the old signed distance is positive, and its negation otherwise). The correction vector was then computed as the target point minus the last position. Finally, if the point mass is not pinned, I assigned its position as the last position plus the correction vector scaled by (1 - friction).

With ks = 500, the cloth is very soft, draping tightly and conforming closely to the sphere, with a significant amount of sagging and a relatively large number of folds and creases. With ks = 50000, the cloth is very stiff, sitting rigidly over the sphere without conforming closely to its surface, with noticeably less sagging and far fewer folds and creases. ks = 5000 falls in between the two extremes, with a moderate degree of sagging and a moderate number of folds and creases.

Part 4: Handling self-collisions

For the hash function, I computed w, h, and t following the method described in the instructions, then derived the number of cells along the x and y directions, nw and nh, as width / w and height / h respectively. After that, I computed the grid coordinates along all three axes by dividing each component by the corresponding cell size and taking the floor, and finally combined them into the hash result as x + y * nw + z * nw * nh, which avoids hash collisions.
For building the spatial map, I just simply iterated through all the point masses, computed their hash values, and inserted their pointers into the corresponding hash buckets.
For self-collision, I first looked up the candidate point masses sharing the same hash bucket as the current point mass. For each candidate (excluding the point mass itself), I computed the vector from the candidate to the current point mass and its length; if the length was below 2 * thickness, I derived a correction along this vector with magnitude 2 * thickness - dist so that applying it would push the pair exactly to the threshold distance apart, and accumulated it into a running sum while incrementing a counter. After iterating through all candidates, if any qualifying pair was found, I averaged the accumulated correction by dividing by the counter, further scaled it down by simulation_steps, and added the result to the current point mass's position.
Inside the simulate function, I first built the spatial map, then iterated through all point masses and call the self-collision function.

Part 5: Shaders

A shader program is a program runs directly on the GPU as part of the rendering pipeline, executed in parallel across many vertices or pixels to determine how a 3D scene is ultimately drawn on the screen.
The vertex shader runs first and runs once per vertex of the input geometry. It processes and passes various vertex attributes to the next stage, such as position, normals, and texture coordinates, and performs transformations such as converting from model space to screen space, or modifying vertex positions as in displacement mapping.
After the vertex shader, the GPU rasterizes the triangles into fragments, smoothly interpolating these per-vertex attributes across the surface, and then passes the resulting attributes to the fragment shader.
The fragment shader uses them, together with uniforms like light positions, camera position, material properties, and texture samplers, applying lighting models like Blinn-Phong to compute the final color of that fragment.
In short, the vertex shader sets up the geometric and per-vertex data needed for shading, and the fragment shader consumes that interpolated data to produce the actual per-pixel color.

The Blinn-Phong shading model breaks the light reflected from a surface into three components: ambient, diffuse, and specular. Ambient is a constant term that never changes, used to simulate indirect environmental light. Diffuse describes Lambertian reflection, whose intensity is determined by the distance to the light source and the angle between the surface normal and the direction toward the light source; the diffuse contribution is the same regardless of the outgoing view direction. Specular describes the highlights of mirror-like reflection, which are only significant when the outgoing view direction and the light source direction are nearly symmetric about the surface normal. This is achieved by taking the dot product of the halfway vector and the surface normal, then raising it to a relatively high power.

Wind simulation:

To achieve a spatially varying wind effect, we apply an external force to all point masses:

F = wind × (0.5 + gust(p, t) + ripple(p, t))

where

  • gust = 0.5 + 0.5 × sin(2.0·p.x + 1.7·p.y + 1.3·p.z − 4.0·wind_time) — a low-frequency traveling wave that sweeps across the cloth. Different positions sample different phases, so the upwind edge feels a peak while the trailing edge is in a trough.
  • ripple = 0.25 × sin(5.0·p.x − 3.0·p.z + 6.0·wind_time) — a higher-frequency, smaller-amplitude perturbation layered on top to break symmetry and create finer flutter.

The 0.5 baseline keeps the force always blowing in the wind direction (never reversing), while the two sinusoids modulate strength between roughly 0.25× and 1.75× of the base wind. Because both terms depend on position, two adjacent point masses see slightly different forces at the same instant.
